# ブランチ戦略を策定してドキュメント化する

## Context

現在、すべてのコミット（タスク管理・機能実装・バグ修正）が `main` ブランチに直接行われている。worktree を使った並列作業のブランチは存在するが、マージ後に残っているだけで、体系的なブランチ運用は行われていない。

プロジェクトが成長するにつれ、以下の課題が発生しうる:
- 未完成の機能が main に混入するリスク
- 複数の機能を並行開発する際の衝突
- リリース管理の困難さ

ベータ期間中のプロジェクト規模に適したブランチ戦略を検討し、CLAUDE.md の Git Rules に反映する。

## Requirements

- 現状の開発フロー（main 直接コミット）の課題を整理する
- プロジェクト規模に適したブランチ戦略を選定する（GitHub Flow 等の軽量な手法を推奨）
- フィーチャーブランチの命名規則を決める
- worktree 並列作業との整合性を確保する
- CLAUDE.md の Git Rules セクションにブランチ戦略を追記する

## Affected Files

- `CLAUDE.md` — Git Rules セクションにブランチ戦略・命名規則を追記

## Acceptance Criteria

- [x] ブランチ戦略が CLAUDE.md に文書化されている
- [x] フィーチャーブランチの命名規則が定義されている
- [x] worktree を使った並列作業との整合性が説明されている
- [x] 既存の Git Rules と矛盾しない

## Notes

- 個人開発のベータ期間中のため、過度に複雑な戦略（Git Flow 等）は避ける
- Chrome Web Store 公開後のリリースフローも視野に入れる
