# 保存済み API 認証情報をマスク表示する

## Context

Options ページの ApiKeyForm では、トークン・シークレットのフォーム state が `useState('')` で初期化されており、保存済みの認証情報が反映されない。そのため、保存済みかどうかがフォームから判別できず、ユーザーは設定状態を確認しにくい。

現在は API 設定セクションの折りたたみヘッダーに「設定済み / 未設定」バッジが表示されるが、フォームを開くと空欄が表示されるため不安になる。

保存済みの場合はプレースホルダーやマスク表示で「設定済み」であることを示し、再入力しない限り既存の値を維持する仕組みが必要。

## Requirements

- 保存済みの認証情報がある場合、フォーム入力欄にマスクされたプレースホルダー（例: `••••••••••••` や `設定済み`）を表示する
- セキュリティ上、保存済みのトークン・シークレットの実値はフォームに読み込まない
- 入力欄が空のまま保存ボタンを押した場合は既存の値を維持する（上書きしない）
- 入力欄に新しい値を入力した場合のみ上書き保存する
- 高セキュリティモード（暗号化保存）でも同様の挙動にする
- 「設定済み」状態を Background SW から取得する（`isAuthenticated` メッセージを活用）

## Affected Files

- `src/components/options/ApiKeyForm.tsx` — 保存済み状態の判定、プレースホルダー表示、空欄時の保存スキップロジック
- `src/utils/i18n.ts` — 「設定済み」プレースホルダーの i18n キー追加（必要に応じて）

## Acceptance Criteria

- [x] 保存済みの場合、トークン・シークレット欄にマスク表示（`••••••••••••`）がプレースホルダーとして表示される
- [x] 保存済みトークン・シークレットの実値がフォームに読み込まれない
- [x] 入力欄が空のまま保存しても既存の認証情報が消えない
- [x] 新しい値を入力して保存すると上書きされる
- [x] 高セキュリティモードでも正しく動作する
- [x] ダークモードで正しく表示される
- [x] `bun run build` が TypeScript エラーなしで成功する

## Notes

- 保存済みかどうかの判定は、既に `App.tsx` で `isAuthenticated` を確認しているため、この値を ApiKeyForm に props で渡す方法が最もシンプル
- Background SW で `getCredentials` のような実値返却メッセージを追加する必要はない（セキュリティ上、実値のフォーム表示は避ける）
